# Building Operations — Master Decision Matrix (שלב 1: Blueprint)

מימוש ראשוני של **שלב 1** בתהליך בניית מנוע ההחלטות התפעוליות לבניינים
(כמתואר בדיון המוצר): פירוק תוכנית האחזקה המונעת הקיימת וניסוח לוגיקת
**KEEP / SKIP / INSPECT / ACT** לכל משימה — הבסיס לאפיון תוכנה ולשיחה עם מפתח.

## מה יש כאן

- `output/master_decision_matrix.xlsx` — הדליברבל: מטריצת החלטות ל-36 משימות
  נבחרות (מתוך 230 משימות אחזקה שקיימות בקובץ המקור), עם שלוש לשוניות:
  1. **מפת החלטות מאסטר** — הטבלה המלאה (מערכת, ציוד, מקור החובה, האם הנתון
     קיים בבקר, האם נדרש חיישן, החלטת ברירת מחדל ותנאי SKIP/INSPECT/ACT,
     והערכת שעות/חיסכון).
  2. **תקציר מנהלים** — KPI-ים מסוכמים (סה"כ שעות היום מול אחרי, % חיסכון,
     פילוח לפי סיווג אסטרטגי A/B/C/D).
  3. **מקרא ומתודולוגיה** — הסבר מלא לכל עמודה, לארבע ההחלטות ולארבעת
     הסיווגים, ורשימת הנחות עבודה ומגבלות.
- `scripts/rows_data.py` — נתוני המשימות שנבחרו (36), כולל הלוגיקה שנוסחה לכל
  אחת מהן.
- `scripts/build_matrix.py` — סקריפט שבונה את קובץ ה-Excel מתוך `rows_data.py`.

## איך נבחרו 36 המשימות

מתוך תוכנית האחזקה המקורית (12 מערכות, 230 משימות: אחזקה כללית, מיזוג אוויר,
גילוי אש, כיבוי אש, פנים וחוץ מבנה, מערכות מים, מערכת חשמל, גנרטורים, מפוחים,
מעליות, ביטחון, בטיחות) נבחרו המשימות בעלות הפוטנציאל הגבוה ביותר להדגמת
המנוע, לפי ארבעה סיווגים אסטרטגיים:

| סיווג | משמעות | דוגמה |
|---|---|---|
| **A** | הנתון כבר קיים בבקר/BMS היום | קריאת לחצים/טמפ' צ'ילר יומית |
| **B** | נדרש חיישן IoT נוסף כדי לצמצם ביקורים פיזיים | רעד/דליפה בצ'ילר, הפרש לחץ במסנן |
| **C** | KEEP — רגולציה/ביטוח/בטיחות חיים, לא ניתן לביטול | מטפה, ספרינקלרים, מעלית, לגיונלה |
| **D** | מבוסס תפוסה/ביקוש (Demand-Based), לא לוח זמנים קבוע | דחסנית אשפה, ניקיון, סיור ביטחון |

הכללת דוגמאות KEEP (סיווג C) היא מכוונת: המטרה להראות שהמנוע **לא** ממליץ על
ביטול משימה רק כי קיימת טכנולוגיה שיכולה "לראות" אותה, כאשר מקור החובה
(תקן/חוק/ביטוח) מחייב בדיקה פיזית.

## הרצה מחדש / עדכון

```bash
cd building_ops/scripts
pip install openpyxl
python3 build_matrix.py
```

הקובץ נכתב ל-`building_ops/output/master_decision_matrix.xlsx`. כל הנתונים
(שעות/מופעים/חיסכון) מחושבים ע"י **נוסחאות** בתוך ה-Excel (לא ערכים קשיחים),
כך שניתן לשנות הנחת עבודה בודדת (למשל זמן ביצוע) ולראות את ההשפעה על הסיכום.

## הנחות ומגבלות (חשוב)

- אומדני הזמן והמופעים העתידיים הם **הערכות MVP** של שלב Blueprint, לא נתוני
  אמת נמדדים. הצעד הבא (שלב 5 בתהליך שהוגדר) הוא אימות מול נתוני אמת ממגדל
  אמיתי.
- מקור החובה (Compliance) מבוסס על ידע כללי בתחום התקינה בישראל ואינו מהווה
  ייעוץ משפטי/הנדסי — יש לאמת מול יועץ בטיחות/חשמל/כיבוי אש מוסמך.
- שורת "סיור ביטחון" מסומנת באזהרה מפורשת: כל צמצום מותנה באישור מראש של
  גורם הביטחון/הביטוח של הבניין, לא רק ביכולת הטכנולוגית.
- קובץ המקור (תוכנית האחזקה המלאה, 230 משימות מכל 12 המערכות) לא נכלל בריפו
  הזה — הוא קובץ תבנית של חברת Visitt שהועלה לצורך העבודה בלבד. ניתן להריץ
  את אותה מתודולוגיה על שאר 194 המשימות, ועל תוכנית הניקיון כשתתקבל.

## השלבים הבאים

1. הרחבת המטריצה ליתר 194 המשימות בתוכנית האחזקה (ולתוכנית הניקיון).
2. אימות מול נתוני אמת ממגדלי הארבעה — זמני ביצוע בפועל ומפת חיישנים/בקרים קיימת.
3. בניית Decision Engine V1 היברידי: Rules (Compliance) + Analytics/ML + Generative AI.
4. בניית מסך Dashboard יומי ("BUILDING OPERATIONS — TODAY") המציג KEEP/SKIP/INSPECT/ACT בזמן אמת.
